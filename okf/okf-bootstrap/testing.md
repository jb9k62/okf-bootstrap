# Testing and CI

Run `npm run check` before you finish. It chains the typecheck, the tests, and validation of
this repository's own two bundles:

```bash
npm run typecheck        # tsc for the tools and the extension, then the widget workspace
npm test                 # node --test test/*.test.mts, plus the widget workspace's tests
npm run test:views       # Chromium: layouts, Graph/Tree/Table, neighbourhood, colour modes
npm run okf:validate     # this repository's okf/ bundle
npm run edukai:validate  # this repository's edukai/ bundle
```

One thing to know: the Chromium tests skip when no browser is installed. A green `check` on
such a machine says nothing about the views.

## The test files

| File | Covers |
| --- | --- |
| `test/bootstrap.test.mts` | The scaffold: what it creates and keeps, the manifest's hashes, `--tools-only`, `--edukai`, the version stamped into templates |
| `test/search.test.mts` | Ranking, filters, the on-disk cache and its invalidation |
| `test/edukai.test.mts` | Lesson rules, `new`/`verify`/`supersede`/`index`/`recheck`, the hook commands, both adapters, and the demo walkthrough |
| `test/update.test.mts` | `okf:update`: dry run, apply, dirty tree, edited scripts |
| `test/render.e2e.mts` | The demo in Chromium: diagrams, callouts, quizzes, every widget mounts and responds. Needs network for the CDN |
| `test/views.e2e.mts` | The viewer's views and layout in Chromium. Serves the pinned libraries from `node_modules` when they are installed, so it also runs offline |

The tests build their throwaway projects under `.cache/` (gitignored), each with an empty
`node_modules`. The hook tests go one step further and run the hook from outside the
repository, to prove it does not depend on this one. To run the end-to-end tests without
Playwright's Chromium, set `OKF_CHROMIUM` to a browser binary.

## The demo is pinned

`examples/demo/edukai/` holds digests of files under `examples/demo/`. Edit one of those files
and a lesson changes state. That changes the brief and the re-check report, and a test pins
them. Three changes were made on purpose so the demo always has something to find; they are
listed in `examples/demo/README.md`. So when you edit a demo file, expect to update the lesson
or the pinned report in the same change.

## CI

`.github/workflows/ci.yml` has three jobs:

- **`check`** on Node 24 and 26: `npm ci`, then `npm run check`. This is the fast, offline
  gate, and it validates the repository's own bundles.
- **`render`**: installs Chromium, then runs `npm run test:render` and `npm run test:views`,
  then puts this repository's own bundle through both Mermaid gates (`npm run okf:mermaid` and
  `npm run okf:mermaid:render`). It needs network for the viewer's CDN.
- **`spec`**: runs `npm run spec -- status` weekly (and on push) and fails when the vendored
  OKF spec has moved upstream. `npm run spec -- update` copies the new spec in and moves the
  submodule.

## Releases

The version is written in four places, and they must match: `package.json`,
`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, and the `VERSION` constant in
`bootstrap.mts` (which stamps scaffolded frontmatter). Tests compare them, so a missed bump
fails `npm test`.

`docs/images/` is generated by `npm run screenshots`. A workflow commits the images to a
`chore/screenshots` branch, never to `main`.
